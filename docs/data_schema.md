## 1. 信息戳

| 字段 | 含义 | 说明 |
|---|---|---|
| `date` | 日期 | 去掉实际日期，但**保留序号**；取值范围 0–119；**保留跨标的的可比性**（不同 sym 在同一 date 是同一交易日） |
| `time` | 时间戳 | 保留实际时间间隔；**3s 一档行情** |
| `sym` | 股票标的 | 仅序号；5 只股票分别为 0–4 |

## 2. 量价（已归一化）

> **价格归一化**：所有 `*price` 类字段都是"相对昨收的涨跌幅"，无量纲，理论范围 -1~1（即跌 100% 到涨 100%；实际取值范围远更小）。
> **量归一化**：所有 `*size` / 量类字段都已转换为"换手率 %"，无量纲。`0.0001` 表示订单量归一化为换手率 0.0001%。

| 字段 | 含义 | 说明 |
|---|---|---|
| `close` | 最新成交价 | 无量纲，相对昨收涨跌幅，**下同** |
| `open` | 开盘价 | 同上 |
| `high` | 当前最高价 | 同上 |
| `low` | 当前最低价 | 同上 |
| `amount_delta` | 成交金额变化 | 从上个 tick 到当前 tick 发生的成交金额；**单位：元（唯一未归一化字段）** |
| `volume_delta` | 成交量变化 | 从上个 tick 到当前 tick 发生的成交量；无量纲，换手率 % 表示 |

| 字段 | 含义 | 说明 |

| `label_10` | 10 tick 后 | 同上；α = **0.05%** |

## 6. 订单流统计（六类订单 = lb / la / mb / ma / cb / ca）

> **命名约定**：
> - 第 1 个字母：`l` = limit（限价）, `m` = market（市价）, `c` = cancel（撤单）
> - 第 2 个字母：`b` = buy（买）, `a` = ask/sell（卖）
> - 即 6 类：lb / la / mb / ma / cb / ca

### 6.1 到达强度 `*_intst`

| 字段 | 含义 | 说明 |
|---|---|---|
| `lb_intst` | 限价买单到达强度 | 从上个 tick 到当前 tick 的平均到达强度；**订单量已转化为换手率 %，下同** |
| `la_intst` | 限价卖单到达强度 | 同上 |
| `mb_intst` | 市价买单到达强度 | 同上 |
| `ma_intst` | 市价卖单到达强度 | 同上 |
| `cb_intst` | 买单撤单强度 | 同上 |
| `ca_intst` | 卖单撤单强度 | 同上 |

### 6.2 强度突变指标 `*_ind`（0/1 二值）

| 字段 | 含义 | 说明 |
|---|---|---|
| `lb_ind, la_ind, mb_ind, ma_ind, cb_ind, ca_ind` | 上述六类订单强度指标 | **过去 1 tick 平均强度 > 过去 60 tick 平均强度？** 是 = 1, 否 = 0 |

### 6.3 强度变化率 `*_acc`（"加速度"）

| 字段 | 含义 | 说明 |
|---|---|---|
| `lb_acc, la_acc, mb_acc, ma_acc, cb_acc, ca_acc` | 上述六类订单强度平均变化率 | 从上个 tick 到当前 tick 的到达强度平均变化率；可理解为"到达的加速度"；订单量已转化为换手率 % |

## 8. 实操关键提示

1. **`amount_delta` 是唯一未归一化字段**——量级 e3–e6 元，必须 `np.log1p` 或 z-score 处理后再喂模型。
2. **价/量两套归一化体系**：价用涨跌幅（≈ 0），量用换手率 %（≈ 1e-3 ~ 1e-2）。混合时注意 scale。
3. **`label_5/10` 阈值 α=0.05% 比 `label_20/40/60` 的 α=0.1% 更严**——同样的 |Δmidprice| 下，短 horizon 更容易被判 0/2，长 horizon 更倾向于 1。
4. **`*_ind` 是 0/1 二值**——树模型可以直接吃，深度模型也别 z-score 它（保留二值语义）。
5. **跨 sym 可比性**：date 序号在不同 sym 间对齐（同一 date 是同一交易日），所以 cross-sym 特征工程（如 cross-sectional rank）是合法的。
6. **midprice 字段是评分公式输入**——不要用 `(bid1+ask1)/2` 来代替，二者在跌停（bid1=0）/ 涨停（ask1=0）边界条件不同。
